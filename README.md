## Возможности

### 🔎 Детектирование подозрительных событий

KDetector анализирует **сетевые события, доступные вашему клиенту**, и записывает наблюдаемые факты отдельно от гипотезы и оценки риска.

- Проверки некорректных значений уровня и подозрительных изменений уровня.
- Проверки некоторых несоответствий данных платформы и неизвестных значений платформы.
- Проверки недопустимых RPC с учётом фазы игры, владельца объекта и известных ограничений протокола.
- Сигнатуры некоторых известных мод-клиентов — только как индикаторы, а не окончательное доказательство.
- Контроль частоты RPC по категориям и общий лимит RPC на игрока.
- Объяснимая оценка риска `0–100`: повторы одного и того же наблюдения не считаются независимыми доказательствами, риск со временем уменьшается.

### 🛡️ RPC Shield

RPC Shield отслеживает потенциальный флуд и может отменять отдельные события в **ограниченных безопасных категориях**, если это разрешено настройками и профилем. Не каждое подозрительное событие блокируется: отмена произвольных RPC может вызвать рассинхронизацию игры.

### 🧰 Действия и режим Dry Run

- Профили действий: `Passive`, `Balanced`, `Strict` и `Custom`.
- Настраиваемые условия действий: уровень уверенности, независимые доказательства, порог риска и задержка между действиями.
- Режим **Dry Run** — фиксирует предполагаемые действия, но не выполняет вмешательство.
- Автоматические Kick и Ban **выключены по умолчанию**.
- Kick/Ban доступны только хосту; проверка полномочий выполняется непосредственно перед действием.

### 🗃️ Локальная база

- События и сведения о наблюдавшихся игроках хранятся локально.
- Поиск, фильтры, сортировка, импорт и экспорт.
- Whitelist и watchlist.
- Резервные копии, автоочистка (по умолчанию выключена), обработка повреждённых записей.
- Журнал событий и отчёт диагностики для поиска причин неполадок.

### 🖥️ Интерфейс и управление

Меню открывается клавишей **F8** и включает десять разделов:

`Dashboard` · `Live Players` · `Detections` · `Database` · `Auto Actions` · `RPC Shield` · `Detection Rules` · `Settings` · `Diagnostics` · `About`.

Команды `/kd ...` обрабатываются локально: KDetector **не отправляет текст этих команд в чат лобби**.

## Важные ограничения

KDetector — клиентский плагин, а не серверная система безопасности. Он не может:

- читать файлы, память или процессы на чужом компьютере;
- гарантированно установить, какой мод установлен у другого игрока, только по его имени;
- достоверно подтвердить настоящий уровень аккаунта или реальное устройство игрока;
- защищать всех участников чужого лобби или выдавать глобальные баны;
- видеть все действия, которые игра не передаёт вашему клиенту. Например, данные о саботажах других игроков могут быть недоступны, если вы не хост.

Совпадение с сигнатурой клиента, необычный уровень или другое единичное событие **не обязательно означает читерство**. Проверяйте контекст и объяснение детекции. На неподдерживаемых версиях игры по умолчанию действует режим «только наблюдение»; отдельные проверки и действия могут быть отключены.

Для начала рекомендуется включить **Dry Run** и проверить поведение на знакомых игроках в приватном лобби. Не используйте непроверенные сигналы как единственное основание для наказания.

## Установка готовой сборки

Если вы получили `KDetector-setup.zip`:

1. Убедитесь, что установлен BepInEx 6 **IL2CPP x64** подходящей версии.
2. Распакуйте содержимое архива в папку Among Us — рядом с `Among Us.exe` должна находиться папка `BepInEx`.
3. Убедитесь, что DLL лежит по адресу:

   ```text
   Among Us/
   └── BepInEx/
       └── plugins/
           └── KDetector/
               └── KDetector.dll
   ```

4. Запустите игру и нажмите **F8**.
5. Если окно не появляется, откройте `BepInEx/LogOutput.log` и найдите сообщения KDetector. Подробности есть в [руководстве по устранению неполадок](docs/TROUBLESHOOTING_RU.md).

Не кладите DLL в `BepInEx/core` и не скачивайте отсутствующие игровые DLL с неизвестных сайтов.

## Сборка из исходников

### Что понадобится

- Windows 10/11.
- .NET SDK 8.0 или новее.
- BepInEx 6 IL2CPP, установленный в папку игры.
- Один запуск игры с BepInEx, чтобы были созданы interop-сборки.
- Интернет для восстановления NuGet-пакетов при первой сборке.

### Рекомендуемый способ — против вашей установленной игры

Откройте PowerShell в корневой папке репозитория, где находятся `build.ps1` и `KDetector.sln`:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\build.ps1 -GamePath "E:\Steam\steamapps\common\Among Us" -Install
```

Замените путь на свой. Скрипт проверяет окружение, собирает Release, запускает тесты ядра и подготавливает файлы в `dist`. С ключом `-Install` он также копирует плагин в папку `BepInEx/plugins/KDetector`.

### Сборка через NuGet

Если нужно собрать проект без локальных interop-сборок игры:

```powershell
.\build.ps1 -UseNuGet
```

Этот вариант использует пакеты BepInEx и игровых библиотек из NuGet. Для проверки на конкретной установленной версии игры предпочтительнее обычная сборка с `-GamePath`.

### Полезные параметры

| Параметр | Назначение |
|---|---|
| `-GamePath "путь\к\Among Us"` | Явно указать папку игры |
| `-Install` | Скопировать собранную DLL в папку плагинов после сборки |
| `-UseNuGet` | Использовать пакеты NuGet вместо локальных библиотек игры |
| `-SkipTests` | Пропустить тесты ядра |
| `-Configuration Debug` | Собрать Debug вместо Release |

Подробные шаги с нуля — в [docs/INSTALLATION_RU.md](docs/INSTALLATION_RU.md).

## Первый запуск

1. Нажмите **F8**, чтобы открыть меню.
2. Откройте **Diagnostics** и проверьте версию игры, состояние модулей и найденные предупреждения.
3. Перейдите в **Settings** и проверьте режим совместимости.
4. На первых тестах включите Dry Run: события будут записываться без автоматического вмешательства.
5. Проверяйте каждую детекцию отдельно. Причина, факты и предположение — разные вещи.

Полезные файлы после запуска:

- Журнал BepInEx: `Among Us/BepInEx/LogOutput.log`.
- Журнал KDetector: `Among Us/BepInEx/plugins/KDetector/Logs/KDetector.log`.
- Отчёты диагностики и экспорты: `Among Us/BepInEx/plugins/KDetector/Exports/`.

## Команды

В чате лобби введите команду с префиксом `/kd`. Команды обрабатываются локально.

| Команда | Что делает |
|---|---|
| `/kd help` | Показывает список команд |
| `/kd status` | Состояние плагина, профиль, режим совместимости и RPC Shield |
| `/kd players` | Список игроков и доступные сведения о риске |
| `/kd player <ID\|имя>` | Подробности об игроке |
| `/kd detections [N]` | Последние события детектирования |
| `/kd shield` | Статистика RPC Shield |
| `/kd dryrun on` / `/kd dryrun off` | Включить или выключить Dry Run |
| `/kd profile passive\|balanced\|strict\|custom` | Выбрать профиль действий |
| `/kd export` | Экспортировать локальную базу |
| `/kd backup` | Создать резервную копию |
| `/kd kick <ID>` / `/kd ban <ID>` | Действие хоста; Ban требует подтверждения |

Полный актуальный список команд доступен через `/kd help`.

## Файлы и данные

По умолчанию KDetector хранит данные в папке плагина:

```text
BepInEx/
├── config/
│   └── dev.kdetector.amongus.cfg
└── plugins/
    └── KDetector/
        ├── Data/
        │   ├── KnownClients.json
        │   ├── ProtocolRules.json
        │   ├── RpcShield.json
        │   ├── ActionPolicies.json
        │   └── KDetector.kh
        ├── Logs/
        └── Exports/
```

Некоторые файлы создаются только при первом запуске или при первой записи. База `.kh` — локальный текстовый файл в формате JSON Lines, а не зашифрованное хранилище. Не публикуйте её без проверки: она может содержать идентификаторы и сведения о других игроках. Внешние списки не загружаются автоматически; правила можно просматривать и редактировать локально.

## Структура проекта

```text
KDetector/
├── src/
│   ├── KDetector.Core/          # детекторы, риск, RPC Shield, база, команды и настройки
│   └── KDetector.Plugin/        # BepInEx, Harmony-патчи, игровые API и GUI
├── tests/
│   └── KDetector.Core.Tests/   # тесты бизнес-логики без запуска игры
├── docs/                        # установка, архитектура, детекции и решение проблем
├── dist/                        # установочные файлы после сборки
├── KDetector.sln
├── build.ps1
└── clean.ps1
```

Исходники `KDetector.Core` компилируются внутрь `KDetector.dll`, поэтому для установки не требуется отдельная DLL ядра. Архитектурные подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
